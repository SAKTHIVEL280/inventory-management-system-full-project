- **FE-213** (Clear error messages — array `detail` handling): **Root-cause fix** for the generic "Invalid input. Please check the entered values." Backends raise some business-rule errors as a `detail` that is an **array of plain strings** (e.g. `["Supplier 'X' has no State set…"]` from GRN GST validation). The error formatters only handled arrays of *objects* (`d.msg`/`d.message`), so a string array produced no message and fell through to the generic 400 fallback — hiding the real reason from the user. Fixed in every place that renders `detail`: `normalizeApiErrorMessage` (`api/client.ts`, global toast), `getApiDetailMessage` (`utils/apiError.ts`), the GRN create/edit catch (`GRNPage.tsx`), and the inline handlers in `CustomersPage`/`SuppliersPage`/`ProductsPage` — each now renders `typeof d === 'string' ? d : d.msg || d.message`. The `api/client.ts` array path additionally prefixes object-style (422) messages with the field name from `loc` (e.g. "items #1 quantity: must be a valid number"). Types widened: `ApiErrorDetail` (client) and `ApiDetail` (apiError) array elements are now `string | object`. Together with the backend BE-213 validation handler, users now see the exact reason/field that failed.
