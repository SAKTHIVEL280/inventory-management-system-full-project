### BRD Bugfix — GRN Batch / Invoice Edit-After-Issue / Country Master

Enforced server-side (HTTP 400, per-line message "Line item N: Batch number is required.") in `create_grn` (`POST /api/v1/grn`) and `update_grn` (`PUT /api/v1/grn/{id}`) inside the line loop, and in `update_confirmed_grn` (`PUT /api/v1/grn/{id}/confirmed-details`) pass-1 validation ("Batch number is required for every line item."). - **BE-211** (Sales Invoice — Edit after issue): New `PUT /api/v1/invoices/{id}/issued-details` (admin-only via `require_role("admin")`) edits an already-issued invoice. Mechanics mirror the GRN confirmed-edit: reverses the invoice's original stock `sale` postings (`adjustment`/`inv_edit_reversal`, +qty/+free), validates stock availability per product against the restored on-hand, rebuilds line items, recomputes tax/totals (`calc_line_item` + `round_paise_to_nearest_5`), re-posts corrected `sale` ledger entries, refreshes the materialized view, and recomputes `amount_due` and payment `status` (so the derived receivable stays correct). Field-level changes (header Amount/Customer/Dates/Type/Remarks/Discount **plus** per-line Quantity/Free/Rate/Discount %/Batch and line added/removed) are captured via `build_audit_changes` and merged by the audit middleware into one readable audit row with acting user + timestamp. Guards (financial integrity): blocks edit when a non-cancelled payment is allocated to the invoice or a confirmed sales return exists, and when the corrected quantity would exceed available stock. Status must be in `{issued, partial_paid, paid}`; draft invoices continue to use `PUT /api/v1/invoices/{id}` (unchanged).
- **BE-212** (Customer & Supplier — Country master): New `app/utils/countries.py` `COUNTRY_MASTER` (complete country list, 198 entries). The Customer (`GET /api/v1/customers/customization-options`) and Supplier (`GET /api/v1/suppliers/customization-options`) endpoints now **union** the master list with any company-specific custom country values from `customization_options` (deduped case-insensitively, sorted) instead of falling back to a 6-item default only when empty — so the country typeahead always offers the full list while still honouring custom entries. Existing records are unaffected (free-text country values still round-trip). No schema change.
- **BE-213** (Clear validation error messages): Added a global `RequestValidationError` handler in `main.py`. Previously FastAPI returned request-body validation errors (422) as a raw list of terse, field-less messages (e.g. "Input should be a valid integer"), which reached the UI as a generic "Invalid input. Please check the entered values." The handler now returns a single readable sentence that **names the offending field and states the problem**, e.g. "Items #1 → Quantity: must be a valid number", "Receipt date: Field required", "Supplier id: must be a valid UUID" (`_humanize_validation_location` renders the pydantic `loc` path; common pydantic phrasings are rewritten — "Input should be" → "must be", "Value error, " stripped). Also made `_enforce_supplier_gstin_for_gst_purchase` (GRN) messages **actionable** — when a Non-Registered GST supplier is missing State/State Code, the error now names the supplier and tells the user to edit the supplier to add it (e.g. "Supplier 'abcdss' has no State set. Verified `_is_versionable_edit` across draft/issued/excluded-sub-action/other-module/non-PUT path shapes.
